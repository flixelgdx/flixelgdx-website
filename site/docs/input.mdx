# Input

FlixelGDX exposes two layers of input:

- **Raw input** — direct per-frame queries against `Flixel.keys`, `Flixel.mouse`, and
  `Flixel.gamepads`. Use these when you need to check a specific physical button immediately.
- **Action sets** — named logical actions (`Jump`, `Attack`, `Move`) that map to one or more
  hardware bindings. Your game logic asks "is Jump pressed?" and the framework resolves whether
  that came from a keyboard, a controller, or a touch screen.

For anything beyond a quick prototype, action sets are the recommended approach. They keep all
binding logic in one place and make rebinding trivial without touching game code.

## Raw input

### Keyboard — `Flixel.keys`

Key codes are plain `int` constants on `FlixelKey` (`FlixelKey.SPACE`, `FlixelKey.LEFT`, etc.).
The special value `FlixelKey.ANY` matches any key.

<Tabs groupId="lang">
<TabItem value="java" label="Java" default>

```java
// True every frame the key is held down.
if (Flixel.keys.pressed(FlixelKey.SPACE)) { ... }

// True only on the single frame the key went down.
if (Flixel.keys.justPressed(FlixelKey.ENTER)) { ... }

// True only on the single frame the key was released.
if (Flixel.keys.justReleased(FlixelKey.ESCAPE)) { ... }

// True when any of the listed keys is held (OR check, avoids nested ifs).
if (Flixel.keys.anyPressed(FlixelKey.LEFT, FlixelKey.A)) { ... }
if (Flixel.keys.anyJustPressed(FlixelKey.SPACE, FlixelKey.W)) { ... }
if (Flixel.keys.anyJustReleased(FlixelKey.SPACE, FlixelKey.W)) { ... }

// Key held the longest (first chronologically among currently held keys).
int first = Flixel.keys.firstPressed();

// First key to go down this frame.
int firstDown = Flixel.keys.firstJustPressed();

// First key released this frame.
int firstUp = Flixel.keys.firstJustReleased();
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin

// First key released this frame.
val firstUp = Flixel.keys.firstJustReleased()
```

</TabItem>
</Tabs>

`firstPressed()`, `firstJustPressed()`, and `firstJustReleased()` all return `FlixelKey.NONE`
when no key matches. They are useful for key-rebinding screens where you want to capture
whatever the player pressed without checking individual codes.

### Mouse — `Flixel.mouse`

Mouse buttons are `int` constants from `FlixelMouseButton` (`FlixelMouseButton.LEFT`,
`FlixelMouseButton.RIGHT`, `FlixelMouseButton.MIDDLE`).

<Tabs groupId="lang">
<TabItem value="java" label="Java" default>

```java
// Button state queries. Same pressed/justPressed/justReleased contract as the keyboard.
if (Flixel.mouse.pressed(FlixelMouseButton.LEFT)) { ... }
if (Flixel.mouse.justPressed(FlixelMouseButton.LEFT)) { ... }
if (Flixel.mouse.justReleased(FlixelMouseButton.RIGHT)) { ... }

// Cursor position in world coordinates (unprojected through the active camera).
float wx = Flixel.mouse.getWorldX();
float wy = Flixel.mouse.getWorldY();

// Cursor position in raw screen pixels (top-left origin).
int sx = Flixel.mouse.getScreenX();
int sy = Flixel.mouse.getScreenY();

// Scroll deltas accumulated this frame (reset by the framework at end of frame).
float scrollY = Flixel.mouse.getScrollDeltaY(); // Typical scroll wheel up/down.
float scrollX = Flixel.mouse.getScrollDeltaX(); // Horizontal scroll (trackpad, etc.).

// Hover check: true when the cursor world position is inside obj's bounding box.
if (Flixel.mouse.overlap(button)) { ... }
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
// Button state queries. Same pressed/justPressed/justReleased contract as the keyboard.
if (Flixel.mouse.pressed(FlixelMouseButton.LEFT)) { ... }
if (Flixel.mouse.justPressed(FlixelMouseButton.LEFT)) { ... }
if (Flixel.mouse.justReleased(FlixelMouseButton.RIGHT)) { ... }

// Cursor position in world coordinates (unprojected through the active camera).
val wx = Flixel.mouse.worldX
val wy = Flixel.mouse.worldY

// Cursor position in raw screen pixels (top-left origin).
val sx = Flixel.mouse.screenX
val sy = Flixel.mouse.screenY

// Scroll deltas accumulated this frame (reset by the framework at end of frame).
val scrollY = Flixel.mouse.scrollDeltaY // Typical scroll wheel up/down.
val scrollX = Flixel.mouse.scrollDeltaX // Horizontal scroll (trackpad, etc.).

// Hover check: true when the cursor world position is inside obj's bounding box.
if (Flixel.mouse.overlap(button)) { ... }
```

</TabItem>
</Tabs>

`getScrollDeltaY()` is the primary scroll axis — positive when the wheel scrolls down, negative
when it scrolls up (exact sign is OS and backend dependent; verify on your target platform).
Both deltas reset to zero at the end of each frame so you only see movement that happened this
tick.

### Gamepad — `Flixel.gamepads`

The gamepad system is **disabled by default**. Set `enabled = true` once, before your game loop
starts, to opt in:

<Tabs groupId="lang">
<TabItem value="java" label="Java" default>

```java
// Opt in before the game loop starts (e.g. in FlixelGame's constructor).
Flixel.gamepads.enabled = true;
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
// Opt in before the game loop starts (e.g. in FlixelGame's constructor).
Flixel.gamepads.enabled = true
```

</TabItem>
</Tabs>

:::tip[Verifying the gamepad system initialized]

After you enable the framework's gamepad system, if you see a log message in the console that reads
something like `[Controllers] added manager for application, 1 managers active`, then that means the gamepad system
was successfully installed and is ready to be used.

:::

Button codes are constants on `FlixelGamepadInput` (`FlixelGamepadInput.A`,
`FlixelGamepadInput.X`, `FlixelGamepadInput.START`, etc.). The first argument is the
zero-based controller slot index:

<Tabs groupId="lang">
<TabItem value="java" label="Java" default>

```java
// Button queries for controller in slot 0.
if (Flixel.gamepads.pressed(0, FlixelGamepadInput.A)) { ... }
if (Flixel.gamepads.justPressed(0, FlixelGamepadInput.A)) { ... }
if (Flixel.gamepads.justReleased(0, FlixelGamepadInput.B)) { ... }

// Stick axis value in [-1, 1] for controller 0 (dead zone applied if globalDeadZone is set).
float lx = Flixel.gamepads.getAxis(0, FlixelGamepadInput.AXIS_LEFT_X);
float ly = Flixel.gamepads.getAxis(0, FlixelGamepadInput.AXIS_LEFT_Y);

// Any-controller variants: true if any connected controller matches.
if (Flixel.gamepads.anyPressed(FlixelGamepadInput.START)) { ... }
if (Flixel.gamepads.anyJustPressed(FlixelGamepadInput.A)) { ... }
if (Flixel.gamepads.anyJustReleased(FlixelGamepadInput.A)) { ... }

// Optional global dead zone applied to all getAxis() calls.
Flixel.gamepads.globalDeadZone = 0.15f;
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
// Button queries for controller in slot 0.

Flixel.gamepads.globalDeadZone = 0.15f
```

</TabItem>
</Tabs>

Axis constants are `AXIS_LEFT_X`, `AXIS_LEFT_Y`, `AXIS_RIGHT_X`, and `AXIS_RIGHT_Y`. The Y axes
are already flipped from screen-space to math-space (up = positive) when used through
`FlixelActionAnalog` axis bindings; raw `getAxis()` returns the hardware value directly.

### Touchscreen — `Flixel.touches`

If you plan to add mobile support for your game, `Flixel.touches` is the `FlixelTouchManager`
that tracks up to 10 simultaneous pointers by default. It is disabled on desktop and web
(where there is no touch hardware), and is enabled automatically by the Android backend.

You can still check `Flixel.touches.enabled` in shared `core` code to safely gate touch logic.

#### Checking individual pointers

Each pointer slot is a `FlixelTouch` accessible via `Flixel.touches.list[pointer]` where
`pointer` is a zero-based index. Slots that have never been touched are non-null but report
all buttons as not pressed.

<Tabs groupId="lang">
<TabItem value="java" label="Java" default>

```java
FlixelTouch first = Flixel.touches.list[0];

// Position in world coordinates (bottom-left origin, same as sprites).
float wx = first.worldX;
float wy = first.worldY;

// Position in raw screen pixels (top-left origin, same as libGDX Input).
float sx = first.screenX;
float sy = first.screenY;

// Per-pointer state checks.
if (first.justPressed()) {
  // Finger just touched the screen this frame.
}
if (first.pressed()) {
  // Finger is currently held down.
}
if (first.justReleased()) {
  // Finger lifted this frame.
}
if (first.dragging()) {
  // Finger moved since last justPressed.
}
if (first.justCancelled()) {
  // Touch event was cancelled by the OS (e.g. incoming call).
}
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">


#### Area queries

Check whether any touch falls inside a rectangle. World queries unproject through the active
camera (bottom-left origin); screen queries use raw screen pixels (top-left origin).

<Tabs groupId="lang">
<TabItem value="java" label="Java" default>

```java
// Is any finger inside this world-space rectangle right now?
if (Flixel.touches.touchingWorld(buttonX, buttonY, buttonW, buttonH)) {
  highlightButton();
}

// Did any finger first touch inside this world-space rectangle this frame?
if (Flixel.touches.justTouchedWorld(buttonX, buttonY, buttonW, buttonH)) {
  activateButton();
}

// Same queries but in raw screen pixels.
Flixel.touches.touchingScreen(sx, sy, sw, sh);
Flixel.touches.justTouchedScreen(sx, sy, sw, sh);
```

:::tip[Coordinate origins]

`worldX` / `worldY` use a bottom-left Y-up origin (same as sprites and the game world). Use
these when checking whether a touch overlaps a sprite or game object.

UI elements that are drawn in screen space.

:::

### Haptics — `Flixel.haptics`

`Flixel.haptics` gives you access to device vibration. On desktop and web it is a silent no-op,
so you can call it from shared `core` code without any platform guards. The Android backend wires
it to the system `Vibrator` service.

:::info[Android permission]

Haptics require `android.permission.VIBRATE` in your `AndroidManifest.xml`. Projects generated
by the [project generator](/getting-started) include this permission automatically.

:::

#### Basic vibration

<Tabs groupId="lang">
<TabItem value="java" label="Java" default>

```java
// Vibrate for 250 milliseconds.
Flixel.haptics.vibrate(250);

// Stop an ongoing vibration early.
Flixel.haptics.cancel();

// Check whether haptics are supported on this device/platform.
if (Flixel.haptics.isSupported()) {
  Flixel.haptics.vibrate(100);
}
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
// Vibrate for 250 milliseconds.
Flixel.haptics.vibrate(250)

// Stop an ongoing vibration early.
Flixel.haptics.cancel()

// Check whether haptics are supported on this device/platform.
if (Flixel.haptics.isSupported()) {
  Flixel.haptics.vibrate(100)
}
```

</TabItem>
</Tabs>

#### Pattern vibration

Pass a `long[]` pattern where entries alternate between off-time and on-time in milliseconds
(the first entry is always off). Pass `repeat = -1` to play the pattern once, or a zero-based
index into the pattern array to loop from that position.

<Tabs groupId="lang">
<TabItem value="java" label="Java" default>

```java
// Off 0ms, on 100ms, off 50ms, on 200ms -- play once.
Flixel.haptics.vibrate(new long[]{0, 100, 50, 200}, -1);

// Same pattern but loop from index 0 until cancel() is called.
Flixel.haptics.vibrate(new long[]{0, 100, 50, 200}, 0);

// Stop the looping vibration when the button is released.
Flixel.haptics.cancel();
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
// Off 0ms, on 100ms, off 50ms, on 200ms -- play once.
Flixel.haptics.vibrate(longArrayOf(0, 100, 50, 200), -1)

// Same pattern but loop from index 0 until cancel() is called.
Flixel.haptics.vibrate(longArrayOf(0, 100, 50, 200), 0)

// Stop the looping vibration when the button is released.
Flixel.haptics.cancel()
```

</TabItem>
</Tabs>

## Action sets

Action sets decouple game logic from hardware. Instead of checking `FlixelKey.SPACE` directly,
you define a `Jump` action and let the action set resolve which physical inputs trigger it.
This makes rebinding a data change rather than a code change, and lets the same logic work across
keyboard, gamepad, and touch without any branching in your update loop.

### Defining an action set

Extend `FlixelActionSet` and declare each action as a field. In the constructor, register
bindings using `FlixelInputBinding` (for digital actions) and `FlixelAnalogAxisBinding` (for
analog actions):

<Tabs groupId="lang">
<TabItem value="java" label="Java" default>

```java
public class PlayerControls extends FlixelActionSet {

  public final FlixelActionDigital jump;
  public final FlixelActionDigital attack;
  public final FlixelActionAnalog move;

  public PlayerControls() {
    // add(...) registers the action with the set so the framework ticks it each frame.
    jump = new FlixelActionDigital("jump");
    jump.addBinding(FlixelDigitalBinding.key(FlixelKey.SPACE));
    jump.addBinding(FlixelDigitalBinding.key(FlixelKey.W));
    jump.addBinding(FlixelDigitalBinding.gamepadButton(0, FlixelGamepadInput.A));
    add(jump);

    attack = new FlixelActionDigital("attack");
    attack.addBinding(FlixelDigitalBinding.key(FlixelKey.Z));
    attack.addBinding(FlixelDigitalBinding.gamepadButton(0, FlixelGamepadInput.X));
    attack.addBinding(FlixelDigitalBinding.gamepadButton(0, FlixelGamepadInput.R2));
    attack.addBinding(FlixelDigitalBinding.touch(0)); // First finger touching the screen.
    add(attack);

    // Analog actions accumulate key halves and stick axes into a normalized [-1, 1] vector.
    move = new FlixelActionAnalog("move");
    move.addAxisBinding(FlixelAnalogBinding.negXKey(FlixelKey.LEFT));
    move.addAxisBinding(FlixelAnalogBinding.posXKey(FlixelKey.RIGHT));
    move.addAxisBinding(FlixelAnalogBinding.negYKey(FlixelKey.UP));
    move.addAxisBinding(FlixelAnalogBinding.posYKey(FlixelKey.DOWN));
    move.addAxisBinding(FlixelAnalogBinding.gamepadAxisX(0, FlixelGamepadInput.AXIS_LEFT_X));
    move.addAxisBinding(FlixelAnalogBinding.gamepadAxisY(0, FlixelGamepadInput.AXIS_LEFT_Y));
    add(move);
  }
}
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin

  // also { } keeps the action as the receiver so bindings read naturally.

```

</TabItem>
</Tabs>

`FlixelActionSet` is registered with `FlixelActionSets` automatically on construction, so the
framework calls `update` and `endFrame` on it every game loop tick. Call `destroy()` when the
set is no longer needed (for example, on state transition) to unregister it and stop stale reads.

### Digital action methods

Instantiate the set once (typically in your state's `create`) and poll it in `update`:

<Tabs groupId="lang">
<TabItem value="java" label="Java" default>

```java
private final PlayerControls controls = new PlayerControls();

@Override
public void update(float elapsed) {
  super.update(elapsed);

  // True every frame the action is active.
  if (controls.jump.pressed()) { ... }

  // True only on the single frame the action became active.
  if (controls.jump.justPressed()) { ... }

  // True only on the single frame the action was released.
  if (controls.jump.justReleased()) { ... }

  // True on the initial press, then again after holdDelay seconds, then every holdInterval
  // seconds while held. Use for navigation or incrementing values that should auto-repeat.
  if (controls.jump.held()) { ... }
}
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
private val controls = PlayerControls()

override fun update(elapsed: Float) {
  super.update(elapsed)

  // True every frame the action is active.
  if (controls.jump.pressed()) { ... }

  // True only on the single frame the action became active.
  if (controls.jump.justPressed()) { ... }

  if (controls.jump.justReleased()) { ... }

  // seconds while held. Use for navigation or incrementing values that should auto-repeat.
  if (controls.jump.held()) { ... }

```

`held()` fires on the initial press and then continues firing at a fixed interval while held.
It is intended for UI navigation and similar cases where holding a button should keep triggering
the action rather than requiring repeated taps.

### Analog action methods

Analog actions expose a two-axis normalized vector that combines all active bindings. Key bindings
contribute exactly `+1` or `-1` per axis; stick bindings contribute smooth hardware values. The
result is clamped to length 1 so diagonals never exceed unit speed:

<Tabs groupId="lang">
<TabItem value="java" label="Java" default>

```java
// Current axis values, each in [-1, 1].
float x = controls.move.getX();
float y = controls.move.getY();

// Axis values from the previous frame, available after endFrame().
float prevX = controls.move.getPrevX();
float prevY = controls.move.getPrevY();

// True when either axis is non-zero (the vector has any length).
if (controls.move.moved()) { ... }

// flicked(): true for exactly one frame when the stick crosses the flick threshold
// from below. Returns false while the stick stays past the threshold. Good for
// single-action menu navigation where each deflection triggers exactly one move.
if (controls.navigate.flicked()) {
  if (controls.navigate.getY() > 0) selectPreviousItem();
  else if (controls.navigate.getY() < 0) selectNextItem();
}

// flickedRepeating(): same as flicked() on the initial cross, then fires again after
// holdDelay seconds if the stick is still past the threshold, and every holdInterval
// seconds after that. Use this when holding the stick should keep scrolling.
if (controls.navigate.flickedRepeating()) {
  if (controls.navigate.getY() > 0) selectPreviousItem();
  else if (controls.navigate.getY() < 0) selectNextItem();
}

// Adjust the stick magnitude required to trigger flicked()/flickedRepeating().
// Default is 0.3 (30% deflection). Key bindings contribute +-1 so they always exceed it.
controls.navigate.setFlickThreshold(0.5f);
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
// Current axis values, each in [-1, 1].
val x = controls.move.x
val y = controls.move.y

// Axis values from the previous frame, available after endFrame().
val prevX = controls.move.prevX
val prevY = controls.move.prevY

// True when either axis is non-zero (the vector has any length).
if (controls.move.moved()) { ... }

// flicked(): true for exactly one frame when the stick crosses the flick threshold
// from below. Returns false while the stick stays past the threshold. Good for
// single-action menu navigation where each deflection triggers exactly one move.
if (controls.navigate.flicked()) {
  when {
    controls.navigate.y > 0 -> selectPreviousItem()
    controls.navigate.y < 0 -> selectNextItem()
  }
}

// holdDelay seconds if the stick is still past the threshold, and every holdInterval
// seconds after that. Use this when holding the stick should keep scrolling.
if (controls.navigate.flickedRepeating()) {
  when {
    controls.navigate.y > 0 -> selectPreviousItem()
    controls.navigate.y < 0 -> selectNextItem()
  }
}

// Adjust the stick magnitude required to trigger flicked()/flickedRepeating().
// Default is 0.3 (30% deflection). Key bindings contribute +-1 so they always exceed it.
controls.navigate.flickThreshold = 0.5f
```

</TabItem>
</Tabs>

`flicked()` mirrors the single-frame contract of `justPressed()` on a digital action: one
deflection, one event. `flickedRepeating()` mirrors `repeated()`. Choose whichever matches
whether your UI should scroll continuously when the stick is held.

### Custom input actions

Let's say you want your game to support input types other than keyboard, mouse, gamepad or touchscreen.
But what if you don't *want* the defaults? What if you wanted an action to be triggered by something completely
different?

Well, here's the good news: all those bindings you saw before? **Those are just functional interfaces**.

When you write something like:

<Tabs>
<TabItem value="java" label="Java">

```java
jump.addBinding(FlixelDigitalBinding.key(FlixelKey.SPACE));
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
jump.addBinding(FlixelDigitalBinding.key(FlixelKey.SPACE))
```

</TabItem>
</Tabs>

It's just secretly a translation for:

<Tabs>
<TabItem value="java" label="Java">

```java
jump.addBinding(() -> Flixel.keys != null && Flixel.keys.enabled && Flixel.keys.pressed(FlixelKey.SPACE));
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
jump.addBinding { Flixel.keys != null && Flixel.keys.enabled && Flixel.keys.pressed(FlixelKey.SPACE)) }
```

</TabItem>
</Tabs>

So if you wanted to add something else — let's say a Twitch chat controlling the game via commands — you can simply
do something like this:

<Tabs>
<TabItem value="java" label="Java">

```java
jump.addBinding(() -> {
  // Could be from a socket or from a library like Twitch4J. It's all up to you!
  String latestMessage = getLatestChatMessage();
  return latestMessage.equals("!jump");
});
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
jump.addBinding {
  // Could be from a socket or from a library like Twitch4J. It's all up to you!
  val latestMessage = getLatestChatMessage()
  latestMessage == "!jump"
});
```

</TabItem>
</Tabs>
